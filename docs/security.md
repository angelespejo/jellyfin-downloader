# Security

The app is designed for a trusted home network. It has **no built-in
authentication**; anyone who can reach the port can browse, download and edit
global settings.

## Deployment

- Put it behind a reverse proxy with authentication or a VPN.
- Do not expose the port directly to the Internet.
- Restrict `API_CORS_ORIGINS`; leaving it empty is the safest default.
- Keep `.env` out of version control and Docker build contexts.

### Authentication recommendation

Use the reverse proxy as the authentication boundary instead of adding a
Jellyfin login to this app. Authelia, Authentik, Caddy `forward_auth`, Traefik
ForwardAuth or a VPN all work without adding sessions, password handling or
multiuser state to the application. The app can remain single-user and use its
server-side Jellyfin API key.

A full Jellyfin/Quick Connect login would require sessions, CSRF protection,
secure cookies, logout and per-user permission checks. If SSO is needed later,
prefer an OIDC/forward-auth proxy over implementing Jellyfin authentication
inside the app.

## Secrets

- `JELLYFIN_API_KEY` is read through `$app/env/private` and used only by
  server-side modules.
- It is never returned by an API or rendered into the client bundle.
- Jellyfin URLs, cache paths and ffmpeg paths are not exposed to clients.
- Logs redact sensitive context keys and never store the API key or absolute
  server paths.

## Input and process safety

- Movie IDs, source IDs, track indices and options are validated against real
  Jellyfin metadata and strict enums.
- Clients cannot provide filesystem paths, output URLs or ffmpeg arguments.
- ffmpeg is spawned with an argument array and `shell: false`.
- Temporary paths are generated by the server.
- Subtitle language/title metadata is sanitized before being passed to ffmpeg.
- External subtitle URLs come from Jellyfin and must be same-origin.
- Archive entries are normalized and ZIP output supports ZIP64.

## HTTP

- API JSON bodies are size-limited.
- JSON `Content-Type` is required for mutating endpoints.
- SvelteKit CSRF protection rejects non-JSON form posts.
- Security headers: `X-Content-Type-Options`, `Referrer-Policy`,
  `X-Frame-Options`, `Permissions-Policy`.
- Downloads support `Range`; filenames are sanitized for
  `Content-Disposition`.

## Availability

- One ffmpeg process at a time; queue capped at 20.
- Disk space is checked before source download when the length is known.
- Temporary and local-store files can be limited with
  `SERVER_LOCAL_DOWNLOADS_MAX_GB` and `SERVER_LOCAL_DOWNLOADS_TTL_DAYS`.
- Jobs and settings are written atomically.

## Known limitations

- No rate limiting or multi-user authorization.
- One app instance per `SERVER_JOBS_DIR`.
- API messages are English; the UI localizes known codes.
